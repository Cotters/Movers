## Implemented

- **Sorting:** control beside the film count; release date, alphabetical and rating in either direction, with Recently added preserving the default. Missing/invalid values stay last and ties are deterministic. Selection persists per list/device and applies after filtering in list/grid. Initial preference loading/returning from details does not reset restored scroll; changing the sort does.
- **Overview:** clear row/group separators, up to five saved personal pins shown first in pin order, and Pin/Unpin on the right-hand reveal (trailing edge, mirrored in RTL). Limit enforced in common policy under a mutex; delete/leave releases slots. Pin actions also have accessibility equivalents.
- **Search suggestions:** immediate local matches followed by a compact “Add to list” paged film search, including below no-match/empty-list messages. A single lazy container owns scrolling in either layout. New queries cancel old searches before a 600 ms debounce. Existing members and pending Undo removals are excluded. Add keeps query/results open, uses the repository membership API and stays guarded until cache observation confirms it. A rendering guard prevents a duplicate shared-image source while paging catches up. Search loading/failure/retry stays separate from local list availability.
- **Home:** Add now reveals on the right; permanent + removed from list rows. Grid + remains. Watchlist film rows retain their two-sided Add/Remove controls and existing delayed-write Undo/attribution policy.
- **Ownership:** `:designsystem` owns the reusable reveal mechanics extracted from the existing film gesture; presentation/feature adapters supply icons/actions/labels. Entry-owned ViewModels/state models own sorting, membership, filtering and pin actions. Feature-owned native preference storage has Android/iOS bindings and the existing host fixture has isolated memory storage. Native writes and common-state publication complete together before cancellation is rethrown. A failed list read never prunes saved preferences.
- Pins/sorts are installation-local presentation settings, independent of friends' list ordering/activity. No database/backend migration, new library versions, notification work, platform target, signing/version change or deployment. Existing Paging Compose dependency is now declared by Watchlists as well. Private Todo updated; Human feedback preserved.
