# Working in Movers

- Start with [Human.md](docs/workflow/Human.md). For substantial/resumed work, read [the current handoff](docs/workflow/handoff.md), then verify Git state and relevant source. Read linked guides only as needed; history is not required startup context.
- Clarify consequential product decisions and agree new feature scope before implementation. Clear follow-up requests authorize their changes. Once agreed, finish authorized work without repeated product permission requests; sandbox approval is a separate environment control.
- Match shared Compose, ViewModel state/events, focused use cases, Koin, Room and typed Nav 3 entries. Preserve feature/contract and movie contract/internal boundaries. Read [development](docs/workflow/development.md); for Gradle/platform changes also use [build conventions](build-logic/README.md) and [multiplatform ownership](docs/workflow/multiplatform.md). No incidental dependency or architecture migrations.
- Consult current official documentation for Android/Kotlin APIs and tooling. Match the artifact actually consumed by the module, not an unused catalog alias. Use relevant skills selectively; latest user instructions override skill examples. Report material documentation-access limits.
- **Never start, run, or interact with emulators/simulators, or execute connected/instrumented tests.** Ask for specific physical-device observations. Host checks/builds are allowed. Historical device exceptions do not grant current authorization.
- **Feature-phase tests:** run the existing suite and update assertions for intended behavior changes. Add no new test cases, especially UI tests, unless explicitly requested. Defer expansion to the post-feature Todo; do not disable or weaken failing checks.
- For app/build changes run `./scripts/verify.sh`; for shared/iOS changes also run `./scripts/verify-ios.sh` (unsigned physical-device SDK, no launch). Compile relevant Android test APKs only. Docs-only changes use `./scripts/verify-docs.sh`. Choose focused iteration checks from [testing guidance](docs/workflow/testing.md), then run the applicable final gate once changes settle; repeat only for new evidence or changes that invalidate it.
- Serialize Gradle/Xcode invocations sharing one checkout or outputs. Finish/identify a running command before starting another; use distinct logs. Separate pure reads can run concurrently. Preserve user edits/staging and recheck HEAD/diff before handoff.
- When a fix fails, capture the exact exception, assertion, UI state and run scope before another speculative patch. After two failed hypotheses, switch to diagnosis and a status update; see [the debugging loop](docs/workflow/development.md#debugging-without-repeated-guessing). Continue authorized fixes; ask only for an actual missing decision or external blocker.
- Keep real credentials, live data, local configuration and private `Notes/` out of tracked files/logs. Treat this as public portfolio source. Repositories use the vendor-neutral database API; provider adapters and Koin bindings stay internal. Follow [backend portability](docs/workflow/open-source.md). Collaboration/backend provisioning require a separate agreed plan.
- Preserve cancellation, installation identity and persisted relationships. Room 7 and later require preserving migrations; destructive fallback is authorized only for retired account versions 1–6. Josh is temporary; there is no account/session system and onboarding is deferred.
- Current repository rules live here and in linked guides; active state/decisions/evidence live in the handoff; past evidence lives in history. Update a changed rule at its source, mark superseded decisions, and keep the handoff concise. Preserve Human.md feedback. Proposals remain proposals until agreed. See [memory ownership](docs/workflow/development.md#durable-memory).
- For the next task, read the first unchecked private `Notes/Todo.md` item if present, then agree feature scope. In clones without Notes, use the handoff and ask which feature to plan. Never force-add private notes. No automatic plugin/skill installs or agent delegation for routine work; use them only for a concrete gap within explicit authorization.
